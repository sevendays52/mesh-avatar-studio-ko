# 원근감과 얼굴 추적 검토

한 장의 원화를 평행 이동하면 코·눈·입이 같은 거리만큼 움직이므로 깊이를 읽기 어렵다.
핀홀 투영은 위치를 `fX/Z`, `fY/Z`로 계산해 깊이에 따른 크기 차이를 만든다.
이를 2D 그림에 적용하려면 실제로 관측하지 않은 깊이를 저자가 가정해야 한다.
([MIT Vision Book](https://visionbook.mit.edu/imaging_geometry.html))

Live2D의 각도 제작 지침도 얼굴 부위를 나누고, 멀어지는 쪽을 좁히고 가까운 쪽을
넓히며 대각선 모양을 별도로 검토한다. 이 저장소의 엔진은 Cubism 엔진이 아니지만,
부위별 단축과 방향별 원화 검토 원칙을 참고했다.
([Live2D 공식 XY 튜토리얼](https://docs.live2d.com/en/cubism-editor-tutorials/xy/))

## 저작과 렌더링

1. 원본·확정 리그를 보존하고 별도 후보를 같은 프로젝트 안에 둔다.
2. 위보기는 턱 아래와 눈·코의 관계, 아래보기는 정수리와 이마, 가까운/먼 눈의 폭을
   확인한다. 눈동자 방향이나 눈 감기만 바꾸는 결과는 고개 원근으로 판정하지 않는다.
3. 목이 없는 둥근 캐릭터는 사각형 머리 마스크가 볼을 가를 수 있다. 확대 격자와
   오버레이로 볼·손·몸 경계를 확인하고 보호 부분을 직접 지정한다.
4. 각 원화의 눈 윤곽과 입선을 다시 교정한다. 원본 얼굴 좌표를 복사해 끝내지 않는다.
5. 필요하면 선택적 `head.perspective`를 소폭 설정한다. 코 중심의 매끄러운 깊이장과
   목 피벗 회전을 사용하고 중립 픽셀을 먼저 역투영하므로 중립에서 줌이 생기지 않는다.
   눈·입·붙임점에도 같은 변환을 적용한다. 이 필드는 기존 `shiftX/Y`와 특징점 시차를
   대체하므로 중복 가산하지 않는다. 생략한 아바타는 기존 경로를 그대로 사용한다.
6. 끝 각도, 선택 경계 양쪽, 중간/대각선, 눈 감기와 발화 조합을 실제 WebGL로 검토한다.
   수치 회귀 통과와 그림 품질 통과를 구분한다.

이 투영은 조정 가능한 2.5D 근사다. 가려짐, 새로운 옆면이나 정수리, 물리적으로 정확한
3D 형상을 복원하지 않는다. 과한 깊이는 코·입과 눈 패치의 보간 차이 또는 접합선 왜곡을
만들 수 있다. 부족한 원화를 자동으로 대체하거나 모든 프로젝트에 일괄 적용하지 않는다.
현재 범주형 원화 선택의 짧은 전환과 위치 차이는 별도 중간 원화/대응점 작업이 필요하다.

## 카메라 검출과 표현

MediaPipe의 검출·얼굴 존재·추적 신뢰도는 서로 다른 옵션이다. 기본 0.5를 유지하고
선택적인 민감 모드에서만 검출/존재를 0.35로 낮췄다. 이는 성능이 검증된 새 모델이나
추적 가능 각도 확장이 아니다. 단일 얼굴을 유지해 모델의 시간 평활화를 사용한다.
([공식 Web 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js),
[옵션 정의](https://developers.google.com/edge/api/mediapipe/js/tasks-vision.facelandmarkeroptions))

전체 카메라 프레임을 로컬 워커에서 추론하고, 페이지에는 랜드마크의 최소/최대 좌표로
만든 작은 사각형과 기존 표정·자세 수치만 전달한다. 프리뷰는 실제 영상 비율을 따라가고
사각형도 반전을 따른다. 가장자리/작은 얼굴 안내는 화면상 크기·위치에 따른 휴리스틱이며,
모델 신뢰도나 재인식 성공률로 표시하지 않는다. 큰 고개 회전으로 얼굴이 가려지거나
어두운 영상에서의 한계는 실제 사람·카메라로 별도 측정해야 한다.

검증은 옵션 전달, 합성 영상의 검출 영역·반전·소실/복귀, 눈/눈썹 독립 감도와 화면 반응을
확인한다. 합성 결과를 실제 얼굴의 인식률 향상으로 보고하지 않는다.
